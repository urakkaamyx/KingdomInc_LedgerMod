Ledger 0.5.0 / Foundation 0.4.0 migration review

Completed migration
- Hard BepInEx dependency on urakka.kingdominc.foundation >= 0.4.0; Foundation.dll is referenced, not bundled.
- Research is registered through FoundationApi.CreateTechNode on Tech Tree > Mods.
- Native Accountant remains a prerequisite. Existing technology ID ledger_mod and workspace type ID Ledger are retained.
- The workspace model now derives from WorkspaceNode and is registered through RegisterWorkspaceNode.
- Foundation owns native factory resolution, the build catalog and the generic world prefab. Ledger no longer patches those three operations or the GamePlayer constructor.
- Ledger retains its existing construction currencies, research multiplier, settings, native save/copy format, port order, dynamic layout, immediate gear opening and accounting behavior.
- This is framework migration groundwork. No new feature unlocks or progression branches have been invented; the detailed tech-tree redesign can be layered on this registration.

Foundation additions exposed by this migration (priority order)

1. HIGH: Public workspace view lifecycle and presentation contract
Evidence: IWorkspaceNodeDefinition supplies a model factory and static metadata, but no view factory/bind callback. WorkspaceIntegration.NativePrefab always creates the generic WorldFlowElement.
Ledger workaround: a scoped WorldFlowElement.SetElement postfix attaches LedgerWorld and hides generic production graphics. Ports, label, background and placement stay native.
Suggested API: a view factory or OnWorldBound/OnWorldUnbound callback with the model, world object and a supported content root. Run binding before the placement callback can open settings. Specify whether it applies to ghosts, previews, loaded instances and copies, plus how it cleans up.
Value: Ledger can remove its view Harmony patch and reflection into native _icon/_progress/_productivity/_craftButton fields. Other mods can supply custom node content without cloning or modifying framework assets.

2. HIGH: Stateless/zero-storage IO extension points
Evidence: ordinary native FlowInput requires buffer capacity; Ledger's zero-capacity ports require immediate receiver admission. Native FlowElement.ClearIO can write directly to adjacent buffers, bypassing InputItem.
Ledger workaround: scoped CanAcceptItem, InputItem and ClearIO patches preserve atomic zero-storage forwarding and keep a rejected/full item at its real producer.
Suggested API: optional admission/TryDeliver hooks for a WorkspaceNode's inputs, plus an adjacent-node cleanup hook that honors stateless ports. Preserve native destination filtering, capacity, stockpile/till limits and cycle rejection. Do not turn the ordinary relay example into a zero-storage node by default.
Value: this is a missing extension point for Ledger, not a defect in Foundation's normal buffered-node behavior.

3. HIGH for the upcoming tech-tree redesign: Ownership and layout/group allocation
Evidence: TechNodeDefinition accepts absolute map coordinates (default 0,0), but there is no mod/group ownership, section layout allocator or reserved map area. PreviousId/RootId require an already active Foundation registration; native research such as Accountant can only be an additional requirement.
Ledger workaround: one Ledger root at the Mods origin, with Accountant in requirements rather than a cross-tab previous connector.
Suggested API: mod/branch owner IDs, a registration scope and a deterministic group/section layout policy, or owner-specific maps. Expose native prerequisite labels/navigation across Base Game/Mods. Consider deferred links for optional cross-mod dependencies.
Value: coordinate collisions and registration-order coupling should be addressed before several mods build larger trees. A native prerequisite does not imply a connector can cross tabs.

4. MEDIUM: Explicit research and building cost-currency options
Evidence: TechNodeOptions and WorkspaceNodeDefinition expose tier/multipliers/fixedCost, while native currency choices are derived from tier. They do not expose a custom currency collection for the native formula.
Ledger workaround: use the public INativeTechNode.NativeNode bridge to preserve Accountant-based research currencies, and set the inherited model CostCurrency to Ledger's legacy Gold/Medals choices.
Suggested API: optional native cost-currency lists on research/building definitions, preserving formula-based pricing, prestige discounts and reset/update behavior. FixedCost is useful but has different discount/count semantics.
Value: a presentation Update currently re-applies the tier-derived research currency rules; native-bridge customizations are outside the immutable definition.

5. MEDIUM: Post-deserialization and dynamic geometry hooks
Evidence: native FlowElement.FromJson calls the mod's DataFromJson before restoring native IO positions. Foundation validates factory instances on creation, but has no OnAfterLoad hook or public resize/rebuild service.
Ledger workaround: a scoped FromJson postfix normalizes legacy 40-unit port spacing after native IO restoration. SetPairs/Refresh update Size, World.UpdateIO, colliders and pipe endpoints themselves.
Suggested API: OnAfterNativeLoad/ValidateLoadedInstance and RefreshGeometry(size, portsChanged), with collision/pipe refresh and explicit mutable-port rules. Keep custom migration logic in the consumer.
Value: existing saved lanes and dynamic item/port/currency layouts can migrate without patching global native deserialization. Buffer inventories and connections must never be silently dropped.

6. OPTIONAL shared service: Native production/item/currency observation
Evidence: LedgerObserver patches native production calls, successful SpendCurrency/AddCurrency and item consumption to retain cost provenance and distinguish item income from passive generation or tray collection.
Ledger workaround: all accounting observers and receipts remain Ledger-owned, including Enchanter start/completion attribution and native destination rewards.
Suggested API if multiple consumers need it: item-transfer, job-start/job-complete and successful attributed currency events, including original item identity, batch identity and session boundaries. Separate tray collection from earned rewards. Keep accounting policy, allocations and rolling reports in Ledger.
Value: a shared observation layer can reduce overlapping Harmony patches; a generic currency-balance change event alone cannot replace these hooks reliably.

Compatibility constraints / issues to keep visible
- Retain ledger_mod and Ledger until a deliberate alias/save migration exists. Renaming them for a new research hierarchy would otherwise lose research lookup or prevent saved buildings from loading.
- Foundation 0.4.0 is a required separate installation; the player/source packages must not bundle a second Foundation.dll or game assemblies.
- Workspace registrations must exist before constructing/loading Ledger models. Registration is performed in dependent-plugin Awake, before player allocation and scene loading.
- RootId/PreviousId currently cannot refer directly to Base Game technology. This migration uses requirements for Accountant; it does not patch Foundation to bypass its rule.
- Foundation itself was not changed in this migration. Items 1, 2 and 5 have explicit Ledger adapters; item 4 uses supported native access; items 3 and 6 are recommendations for the next framework/tree iteration.
- Remove placed Ledger nodes before uninstalling Ledger or Foundation. Native research IDs alone are safely skippable, but native workspace types need their registered factory.
